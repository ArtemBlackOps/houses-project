# Houses-project
В рамках этого проекта будет проанализирован набор данных о «Титанике» для выявления факторов, влияющих на выживаемость пассажиров. Также в рамках проекта будут созданы различные модели машинного обучения и глубокого обучения, чтобы определить, какая из них наиболее подходит для данного исследования.

# 1. Summary

В рамках исследования проводилось сравнение и оптимизация моделей машинного обучения для задачи бинарной классификации. Основное внимание было уделено проверке гипотезы о влиянии архитектурной сложности нейросетей и способов предобработки данных на их обобщающую способность.

* **Валидация:** Для предотвращения утечки данных (Data Leakage) использовалась кросс-валидация **5-Fold Stratified K-Fold**. Все трансформации данных (заполнение пропусков по медианам, кодирование категориальных признаков, масштабирование) выполнялись строго внутри валидационных фолдов.
* **Семейства моделей:**
  1. **Деревянные ансамбли:** CatBoost (одиночный и OOF-ансамбли) и XGBoost.
  2. **Нейронные сети (PyTorch):** Легковесная двухслойная сеть (`simple_mlp`) и глубокая четырехслойная сеть с регуляризацией (`advanced_mlp`).
* **Оптимизация:** Автоматический подбор гиперпараметров осуществлялся с помощью фреймворка **Optuna**.

# 2. Validation + Preproccesing strategy

### Описание валидации (Validation Scheme)

* **Кросс-валидация для регрессии (5-Fold K-Fold):** Используется 5-фолтовая кросс-валидация со случайным перемешиванием (`KFold(n_splits=5, shuffle=True, random_state=42)`).

* **Строгая изоляция фолдов (No Data Leakage):** Вся цепочка пайплайна предобработки (`processing_func`) запускается строго **внутри каждого фолда**. 
  Заполнение пропусков медианами, логарифмирование скошенных признаков, кодирование редких категорий, Target Encoding района (`Neighborhood`) и масштабирование (`StandardScaler` в `process_v2`) рассчитываются исключительно на обучающей части фолда (`fold_train`) и транслируются на валидационную (`fold_val`), что полностью исключает утечку данных из будущего.

* **Сравнение пайплайнов предобработки:**
  * **`process_v1` (Базовый для деревьев):** Выполняет генерацию физических/агрегированных признаков (`TotalSF`, `HouseAge`, `TotalBath` и др.), логарифмирование целевой переменной `SalePrice` и численных признаков, One-Hot Encoding категориальных переменных и изолированный Target Encoding для района `Neighborhood`.
  * **`process_v2` (Продвинутый / для нейросетей и линейных моделей):** Включает всю логику `process_v1`, но дополнительно приводит логические типы (`bool`) к `float32` и производит обязательную стандартизацию всех входных фичей (`StandardScaler`), адаптируя данные под градиентный спуск и метрические алгоритмы (SVR, KNN, SGD).

* **Оцениваемые модели и метрика:** Оценка проводится по **RMSE в логарифмическом масштабе (RMSLE)** на 11 алгоритмах (линейные модели, SVR, KNN, Random Forest, а также бустинги: CatBoost, XGBoost, LightGBM).

# 3. Data part
Первичный EDA позволил прийти к следующим выводам:

3.1 **Распределение целевой переменной (Target):**
   * `SalePrice` имеет правое смещение (skew ≈ 1.88).
   * **Что делать:** Применить логарифмирование (`np.log1p`). Это приведет распределение цен к нормальному, стабилизирует дисперсию и улучшит качество работы линейных моделей и градиентного бустинга.

3.2 **Пропущенные значения (Missing data):**
   * Пропуски в признаках вроде `PoolQC` (бассейн), `Alley` (переулок), `Fence` (забор), `Garage*` и `Bsmt*` — это не ошибки сбора данных, а отсутствие самого объекта у дома (например, "нет гаража").
   * **Что делать:** Заполнять пропуски не средним/медианой, а специальной категорией `'None'` (для категориальных) или `0` (для численных).

3.3 **Сильнейшие линейные предикторы (Strongest predictors):**
   * Признаки с наивысшей корреляцией с ценой: общее качество (`OverallQual`), жилая площадь (`GrLivArea`), параметры гаража и подвала, а также год постройки.
   * **Что делать:** Обратить на них особое внимание при валидации и оценке важности фичей (Feature Importance).

3.4 **Выбросы (Outliers):**
   * Найдено 2 аномальных дома с жилой площадью `GrLivArea` > 4000 кв. футов, которые продались по необычно низкой цене (классические аномалии датасета Ames Housing).
   * **Что делать:** Удалить эти 2 наблюдения из обучающей выборки (`train`), чтобы они не искажали гиперплоскость или границы деревьев решений.

3.5 **Мультиколлинеарность (Multicollinearity):**
   * Обнаружены пары сильно коррелирующих между собой признаков (например, `GarageCars` и `GarageArea`, или `TotalBsmtSF` и `1stFlrSF`).
   * **Что делать:** Для линейных моделей (Ridge/Lasso) стоит дропнуть один из дублирующих признаков или использовать L1/L2-регуляризацию, чтобы избежать нестабильности весов. Деревянные модели (CatBoost, LightGBM) к этому менее чувствительны.

3.6 **Категориальные признаки (Categorical effects):**
   * `Neighborhood` (район), `MSZoning` и `SaleCondition` сильно влияют на медианную стоимость.
   * **Что делать:** Район (`Neighborhood`) имеет много уникальных значений (высокая кардинальность), поэтому для него отлично подойдет Target Encoding или Frequency Encoding.

3.7 **Сезонность (Seasonality):**
   * Месяцы продаж (`MoSold`) имеют пик летом (май–июль), но сам месяц почти не коррелирует с итоговой ценой продажи.
   * **Что делать:** Признак можно не усложнять или оставить в исходном виде, так как явной ценовой сезонности нет.

3.8 **Проверка сгенерированных фичей (Engineered features):**
   * Новые гибридные фичи `TotalSF` и `QualityLivArea` показывают более высокую корреляцию с ценой, чем исходные колонки по отдельности.

# 5. Моделирование (Modeling)

## 5.1. Подход
На протяжении всего проекта проводилось систематическое сравнение различных семейств моделей — градиентного бустинга (CatBoost, XGBoost) и глубоких нейросетей (PyTorch MLP). Для надежной оценки качества использовалась схема 5-Fold Stratified Cross-Validation с OOF (out-of-fold) предсказаниями. Чтобы предотвратить утечку данных (Data Leakage), вся предобработка (включая импутацию пропусков по групповым медианам, кодирование признаков и масштабирование) выполнялась строго изолированно внутри каждого фолда.

Несмотря на то, что подбор гиперпараметров улучшал показатели на кросс-валидации (CV), результаты на публичном лидерборде (Test Score) показали, что более простые ансамбли и модели без агрессивной оптимизации лучше обобщаются на новых данных.

---

## 5.2. Базовая одиночная модель (Single Model Baseline)
Для создания отправной точки (бейзлайна) была обучена одиночная модель CatBoost на всей обучающей выборке с ручным подбором гиперпараметров.

```python
solo_catboost_params = {
    'depth': 4,
    'learning_rate': 0.1,
    'l2_leaf_reg': 7,
    'iterations': 200,
    'verbose': 0,
    'random_state': 42
}
```
## 5.3. Кросс-валидационные ансамбли и оптимизация гиперпараметров
CatBoost Ensemble with OOF (Базовые гиперпараметры)
Вместо одной модели был реализован 5-Fold Stratified OOF ансамбль. Предсказания для тестовой выборки формировались путем усреднения спрогнозированных вероятностей (predict_proba) со всех 5 фолдов (Soft Voting). Хотя его показатель CV слегка уступил одиночной модели, данный ансамбль показал наилучший итоговый результат на тестовой выборке, продемонстрировав высокую обобщающую способность.
```python
ensemble_catboost_params = {
    'depth': 4,
    'learning_rate': 0.1,
    'l2_leaf_reg': 7,
    'iterations': 200,
    'verbose': 0,
    'random_state': 42
}
```

CatBoost Ensemble with OOF & Optuna Tuning
С помощью библиотеки Optuna был выполнен автоматический поиск гиперпараметров (depth, learning_rate, l2_leaf_reg, random_strength, bagging_temperature) на 5 фолдах с использованием Early Stopping (early_stopping_rounds=40). Это позволило получить наивысшую точность на кросс-валидации среди всех деревьев решений, однако модель показала легкое переобучение относительно тестовых данных.
```python
ensemble_catboost_params_optune_v2 = {
  iterations: 245,
  learning_rate: 0.09008217132634158,
  depth: 9,
  l2_leaf_reg: 6.535249522083059,
  random_strength: 0.025939853867577217,
  bagging_temperature: 0.7114448436770735
}
```

XGB Ensemble with OOF & Optuna Tuning
Аналогичный пайплайн кросс-валидации был построен для XGBoost. Через Optuna подбирались параметры max_depth, learning_rate, n_estimators, subsample, colsample_bytree, а также L1/L2 регуляризация. XGBoost показал сильные результаты на CV, но незначительно уступил CatBoost на тестовой выборке.

## 5.4. Глубокое обучение (PyTorch MLPs)
Для разнообразия семейства моделей были спроектированы архитектуры многослойных перцептронов (MLP) на PyTorch с применением Early Stopping и планировщиков скорости обучения (LR Schedulers).

Simple MLP (simple_mlp_v1):
Легковесная 2-слойная сеть (hidden_units=[64, 32], активация ReLU, оптимизатор Adam, lr=1e-3), обученная на One-Hot Encoded признаках (Пайплайн V1). Несмотря на более скромный CV, она показала хорошую стабильность на тестовом датасете.
```python
simple_mlp_v1_params = {
    hidden_units=[64, 32],
    activation='relu',
    device='cuda',
    use_batchnorm=False,
    dropout_rates=0.0,
    optimizer_name='adam',
    lr=1e-3,
    batch_size=64,
    epochs=100,
    early_stopping=True,
    patience=20,
    use_scheduler=False,
    task='binary'
}
```

Advanced MLP (advanced_mlp_v4):
Более глубокая 4-слойная сеть с регуляризацией (hidden_units=[256, 128, 64, 32], активация GELU, BatchNorm, Dropout [0.3, 0.3, 0.2, 0.1], оптимизатор AdamW с планировщиком Cosine Annealing), обученная на признаках с групповыми медианами (Пайплайн V4):
```python
advanced_mlp_v4_params = {
    hidden_units=[256, 128, 64, 32],
    activation='gelu',
    device='cuda',
    use_batchnorm=True,
    dropout_rates=[0.3, 0.3, 0.2, 0.1],
    optimizer_name='adamw',
    weight_decay=1e-3,
    lr=2e-3,
    batch_size=128,
    epochs=100,
    early_stopping=True,
    patience=20,
    use_scheduler=True,
    scheduler_type='cosine',
    task='binary'
}
```
