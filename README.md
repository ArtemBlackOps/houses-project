# 1. Summary

В рамках исследования проводилось сравнение и оптимизация моделей машинного обучения для задачи бинарной классификации. Основное внимание было уделено проверке гипотезы о влиянии архитектурной сложности нейросетей и способов предобработки данных на их обобщающую способность.

* **Валидация:** Для предотвращения утечки данных (Data Leakage) использовалась кросс-валидация **5-Fold Stratified K-Fold**. Все трансформации данных (заполнение пропусков по медианам, кодирование категориальных признаков, масштабирование) выполнялись строго внутри валидационных фолдов.
* **Семейства моделей:**
  1. **Деревянные ансамбли:** CatBoost (одиночный и OOF-ансамбли) и XGBoost.
  2. **Нейронные сети (PyTorch):** Легковесная двухслойная сеть (`simple_mlp`) и глубокая четырехслойная сеть с регуляризацией (`advanced_mlp`).
* **Оптимизация:** Автоматический подбор гиперпараметров осуществлялся с помощью фреймворка **Optuna**.

---


# 2. Validation + Preproccesing strategy

Стратифицированная кросс-валидация (5-Fold Stratified K-Fold): Разбиение сохраняет баланс классов целевой переменной Survived.

Строгая изоляция фолдов: Предобработка (processing_func) запускается внутри каждого фолда. Заполнение пропусков медианами, Target Encoding и StandardScaler рассчитываются строго на обучающей части фолда (fold_train) и применяются к валидационной (fold_val), что полностью исключает Data Leakage.

# 3. Data part
Первичный EDA позволил прийти к следующим выводам по построению бейзлайна:
Выкинуть столбцы: 
1) Ticket (потому что практически уникальные значения), 
2) Cabin (много пропусков, НО возможно если дополнительно их заполнить реальной инфой, то это местоположение может дать доп очки), 
3) Fare (цена билет по сути отображена в колонке Pclass, опять же потенциально можно преобразовать в доп переменную либо понадеятся что этот столбец дополнительно потом еще даст большее значение метрики)
4) Name (логически это вообще ни на что влиять не может, но опять же как доп фича преобразованная может дать еще прирост метрики)

Преобразовать: Parch, SibSp (логика в том, что как будто если у людей больше детей/родственников, то они могли забить место в шлюпке)

Оставить: 
1) Sex (тут сильная корреляция, по статистике женщин выжило больше), 
2) Pclass (по статистике выжило больше пассажиров 1 и 2 класса), 
3) Age (возможно если преобразовать в категориальный признак, то окажется что выжившие мужчины - дети/подростки), 
4) Embarked (по статистике частично повлияло на выживаемость)

# 2.1 Feature Engineering Pipelines
## V1 (One Hot Encoding Baseline): 
Базовое заполнение пропусков Age общей медианой, биннинг SibSp, кодирование категорий через pd.get_dummies (One-Hot Encoding) с выравниванием колонок (align).

## V2 (Target Encoding & Intersections): 
Введение синергетических признаков (FamilySize, IsAlone, Age*Pclass), биннинг возраста и кодирование порт приписки (Embarked) с помощью TargetEncoder.

## V3 (Group Binning & Scaling): 
Группировка возраста по интервалам (AgeGroup), OHE для категорий и масштабирование непрерывного возраста через StandardScaler (оптимально для линейных моделей, SVM и Neural Networks/MLP).

## V4 (Group Medians & Raw Numerical): 
Продвинутая импутация Age медианами по группам (Sex, Pkg/Pclass), прямое добавление признака Fare, сохранение числовых признаков без биннинга для деревьев решений.

# 5. Моделирование (Modeling)

## 5.1. Подход
На протяжении всего проекта проводилось систематическое сравнение различных семейств моделей — градиентного бустинга (CatBoost, XGBoost) и глубоких нейросетей (PyTorch MLP). Для надежной оценки качества использовалась схема 5-Fold Stratified Cross-Validation с OOF (out-of-fold) предсказаниями. Чтобы предотвратить утечку данных (Data Leakage), вся предобработка (включая импутацию пропусков по групповым медианам, кодирование признаков и масштабирование) выполнялась строго изолированно внутри каждого фолда.

Несмотря на то, что подбор гиперпараметров улучшал показатели на кросс-валидации (CV), результаты на публичном лидерборде (Test Score) показали, что более простые ансамбли и модели без агрессивной оптимизации лучше обобщаются на новых данных.

---

## 5.2. Базовая одиночная модель (Single Model Baseline)
Для создания отправной точки (бейзлайна) была обучена одиночная модель CatBoost на всей обучающей выборке с ручным подбором гиперпараметров.

```python
solo_catboost_params = {
    'depth': 4,
    'learning_rate': 0.1,
    'l2_leaf_reg': 7,
    'iterations': 200,
    'verbose': 0,
    'random_state': 42
}
```
## 5.3. Кросс-валидационные ансамбли и оптимизация гиперпараметров
CatBoost Ensemble with OOF (Базовые гиперпараметры)
Вместо одной модели был реализован 5-Fold Stratified OOF ансамбль. Предсказания для тестовой выборки формировались путем усреднения спрогнозированных вероятностей (predict_proba) со всех 5 фолдов (Soft Voting). Хотя его показатель CV слегка уступил одиночной модели, данный ансамбль показал наилучший итоговый результат на тестовой выборке, продемонстрировав высокую обобщающую способность.
```python
ensemble_catboost_params = {
    'depth': 4,
    'learning_rate': 0.1,
    'l2_leaf_reg': 7,
    'iterations': 200,
    'verbose': 0,
    'random_state': 42
}
```

CatBoost Ensemble with OOF & Optuna Tuning
С помощью библиотеки Optuna был выполнен автоматический поиск гиперпараметров (depth, learning_rate, l2_leaf_reg, random_strength, bagging_temperature) на 5 фолдах с использованием Early Stopping (early_stopping_rounds=40). Это позволило получить наивысшую точность на кросс-валидации среди всех деревьев решений, однако модель показала легкое переобучение относительно тестовых данных.
```python
ensemble_catboost_params_optune_v2 = {
  iterations: 245,
  learning_rate: 0.09008217132634158,
  depth: 9,
  l2_leaf_reg: 6.535249522083059,
  random_strength: 0.025939853867577217,
  bagging_temperature: 0.7114448436770735
}
```

XGB Ensemble with OOF & Optuna Tuning
Аналогичный пайплайн кросс-валидации был построен для XGBoost. Через Optuna подбирались параметры max_depth, learning_rate, n_estimators, subsample, colsample_bytree, а также L1/L2 регуляризация. XGBoost показал сильные результаты на CV, но незначительно уступил CatBoost на тестовой выборке.

## 5.4. Глубокое обучение (PyTorch MLPs)
Для разнообразия семейства моделей были спроектированы архитектуры многослойных перцептронов (MLP) на PyTorch с применением Early Stopping и планировщиков скорости обучения (LR Schedulers).

Simple MLP (simple_mlp_v1):
Легковесная 2-слойная сеть (hidden_units=[64, 32], активация ReLU, оптимизатор Adam, lr=1e-3), обученная на One-Hot Encoded признаках (Пайплайн V1). Несмотря на более скромный CV, она показала хорошую стабильность на тестовом датасете.
```python
simple_mlp_v1_params = {
    hidden_units=[64, 32],
    activation='relu',
    device='cuda',
    use_batchnorm=False,
    dropout_rates=0.0,
    optimizer_name='adam',
    lr=1e-3,
    batch_size=64,
    epochs=100,
    early_stopping=True,
    patience=20,
    use_scheduler=False,
    task='binary'
}
```

Advanced MLP (advanced_mlp_v4):
Более глубокая 4-слойная сеть с регуляризацией (hidden_units=[256, 128, 64, 32], активация GELU, BatchNorm, Dropout [0.3, 0.3, 0.2, 0.1], оптимизатор AdamW с планировщиком Cosine Annealing), обученная на признаках с групповыми медианами (Пайплайн V4):
```python
advanced_mlp_v4_params = {
    hidden_units=[256, 128, 64, 32],
    activation='gelu',
    device='cuda',
    use_batchnorm=True,
    dropout_rates=[0.3, 0.3, 0.2, 0.1],
    optimizer_name='adamw',
    weight_decay=1e-3,
    lr=2e-3,
    batch_size=128,
    epochs=100,
    early_stopping=True,
    patience=20,
    use_scheduler=True,
    scheduler_type='cosine',
    task='binary'
}
```
